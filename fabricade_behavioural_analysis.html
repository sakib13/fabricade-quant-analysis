Behavioural Analysis of Decision Latency in a State-Dependent Narrative Environment¶

An exploratory quantitative analysis of interaction-log and decision-latency data

This notebook analyses behavioural logs from Fabricade, a within-subjects experiment I designed and ran in which ten participants each experienced two versions ("conditions") of a narrative environment whose responses depend on hidden, accumulating internal state. Each gameplay session was automatically instrumented, producing per-choice interaction logs and decision-latency (response-time) measurements.

The study's primary findings are qualitative and reported elsewhere. The purpose of this notebook is narrower and methodological: to demonstrate a reproducible Python pipeline for behavioural interaction-log data — parsing raw event logs, modelling repeated-measures response times with a mixed-effects model, quantifying condition and learning effects, and reasoning honestly about statistical power at this sample size.

Framing note. With N = 10 participants this is an exploratory analysis. No claim of confirmatory inference is made. Where tests are reported they are accompanied by effect sizes and an explicit power analysis (Part 6). The value here is the method and the honest treatment of a small within-subjects dataset, not a significant p-value.

Part 1 — Data pipeline and design overview¶

Raw source. Each gameplay session was exported as one CSV row containing metadata plus a JSON array of time-stamped events (scene_enter, choice_presented, choice_made, story_end). The number of leading CSV columns is inconsistent across rows, so parse_logs.py locates the JSON payload by content and reads session start-time and duration from the events themselves rather than from fragile positional columns. It emits two tidy, anonymised tables (participants are coded P1–P10; no real identifiers reach the derived data):

file grain rows
data/sessions.csv one participant × condition 20
data/choices.csv one recorded choice (long) 260

A key cleaning step. Of the 13 recorded choices per session, only 7 are genuine narrative decisions; the other 6 are "Continue" presses that merely advance text. Treating those as decisions would badly contaminate any response-time analysis, so they are flagged (is_decision) and excluded from the latency models below.

Design. Within-subjects, two conditions (A, B), counterbalanced order.

Part 2 — Decision latency: a linear mixed-effects model¶

Decision latencies are repeated measurements nested within participants, and they are strongly right-skewed (Part 1b), so I model log hesitation with a linear mixed-effects model with a random intercept per participant:

$$\log(\text{hesitation}_{ij}) = \beta_0 + \beta_1\,\text{condition}_{ij} + \boldsymbol{\beta}_s\,\text{scene}_{ij} + \beta_o\,\text{order}_{ij} + u_i + \varepsilon_{ij}, \qquad u_i \sim \mathcal{N}(0,\tau^2)$$

The random intercept $u_i$ accounts for the non-independence of the seven decisions made by the same participant — the correct structure for this design, and the reason a plain OLS or a naïve t-test would be inappropriate. Because the outcome is logged, exponentiated coefficients read as multiplicative effects on latency.

Reading the model. The C(scene) terms show that latency is not flat across the narrative: the coefficient on the room scene — where the environment discloses that the experienced memories were fabricated — is the largest ($e^{1.17}\approx 3.2\times$ the intake baseline), i.e. participants deliberated markedly longer there, consistent regardless of condition. The C(play_order)[T.2] term ($e^{-0.20}\approx 0.82$) captures an ~18% speed-up on the second playthrough (Part 4). The condition term ($e^{-0.27}\approx 0.76$) indicates ~24% shorter latencies in Condition B — but this must be interpreted cautiously: Condition B presents less on-screen text (ELARA's commentary is reduced), and session durations are correspondingly shorter (Part 3), so much of this difference likely reflects reduced reading load rather than faster deliberation. The measured latency blends the two (see Part 6). The high ICC (0.47) confirms that pooling decisions without a per-participant term would violate independence.

Part 3 — State-dependence: behaviour under two hidden-state conditions¶

The two conditions differ in how the environment's hidden state is expressed back to the player. Here I test whether that manipulation changes behaviour, using paired, non-parametric tests (Wilcoxon signed-rank on the 10 within-participant pairs) with a rank-biserial effect size. Non-parametric tests are appropriate given N = 10 and non-normal measures.

In [8]:
def paired_wilcoxon(wide, label):
    a, b = wide["A"].values, wide["B"].values
    d = a - b
    dnz = d[d != 0]
    res = stats.wilcoxon(a, b)
    # rank-biserial correlation (matched pairs)
    r = stats.rankdata(np.abs(dnz))
    rbc = (r[dnz > 0].sum() - r[dnz < 0].sum()) / r.sum()
    return {
        "measure": label,
        "median_A": np.median(a), "median_B": np.median(b),
        "median_diff(A-B)": np.median(d),
        "W": res.statistic, "p": res.pvalue, "rank_biserial_r": rbc, "n_pairs": len(d),
    }

sess_lat = (decisions.groupby(["participant", "condition"])["hesitation_s"]
            .mean().reset_index()
            .pivot(index="participant", columns="condition", values="hesitation_s"))
sess_dur = sessions.pivot(index="participant", columns="condition", values="duration_s")

rows = [
    paired_wilcoxon(sess_lat, "Mean decision latency (s)"),

]

Part 4 — Learning across repeated exposure (order effects)¶

Every participant played twice. Because condition order is counterbalanced, first-vs-second differences isolate a learning / familiarity effect rather than a condition effect. This maps onto the project's interest in how representations are learned across repeated exposure.

def paired_report(wide, label):
    a, b = wide["first"].values, wide["second"].values
    res = stats.wilcoxon(a, b)
    dz = np.mean(a - b) / np.std(a - b, ddof=1)
    return {"measure": label, "mean_first": a.mean(), "mean_second": b.mean(),
            "mean_change": np.mean(a - b), "W": res.statistic, "p": res.pvalue,
            "cohen_dz": dz}

Part 6 — Limitations and statistical power¶

Honest appraisal of what this dataset can and cannot support.

Statistical power. With ten within-participant pairs, only large effects are detectable. To make this concrete, I take the observed paired effects and compute (i) achieved power at N = 10 and (ii) the N required for 80% power, using a paired-t approximation.

In [15]:
tp = TTestPower()

def power_row(wide, cols, label):
    a, b = wide[cols[0]].values, wide[cols[1]].values
    dz = np.mean(a - b) / np.std(a - b, ddof=1)
    achieved = tp.power(effect_size=abs(dz), nobs=10, alpha=0.05, alternative="two-sided")
    try:
        n80 = tp.solve_power(effect_size=abs(dz), power=0.8, alpha=0.05, alternative="two-sided")
    except Exception:
        n80 = np.nan
    return {"comparison": label, "cohen_dz": dz, "power_at_N=10": achieved,
            "N_for_80%_power": np.ceil(n80) if n80 == n80 else np.nan}

pwr = pd.DataFrame([
    power_row(dur_ord, ["first", "second"], "Order effect: duration (1st vs 2nd)"),
    power_row(sess_lat, ["A", "B"], "Condition effect: mean decision latency"),
]).set_index("comparison").round(3)

Interpretation. The two rows deliberately contrast a large effect with a subtle one. The condition effect on decision latency is large (Cohen's $d_z \approx 1.3$) and adequately powered even at N = 10, so that contrast is on relatively firm statistical ground — though, as Part 2 cautioned, its substantive interpretation is confounded by reading load. The order effect on total session duration is small ($d_z \approx 0.4$) and clearly under-powered here: roughly 50 participants would be needed to detect it at 80% power, so its non-significance is a limitation of sample size, not evidence of no effect. Notably, the more sensitive per-decision latency measure does reveal a robust order effect in the Part 2 mixed model — a reminder that measurement choice, not just sample size, governs power. Reporting the required N is the responsible way to handle an underpowered comparison rather than claiming a null.

Other limitations.

  • Sample size (N = 10). Exploratory only; effect estimates have wide intervals. No correction for multiple comparisons is applied because no confirmatory claims are made — the tests are descriptive aids, and p-values should be read as such.
  • Latency includes reading time. hesitation_s is the interval from options appearing to selection, so it blends reading and deciding; it is a proxy for deliberation, not a pure decision time. A future design could log per-option dwell time (or eye-tracking) to separate them.
  • Behavioural-change measure. Divergence is scored by the option slot chosen (Part 3); because Condition A also alters option wording, slot identity is a conservative proxy.
  • Latent state observed only at session end. The six hidden-state variables are logged at story_end, so true within-session trajectories of the state vector cannot be reconstructed — only the behavioural (latency) trajectory can.

Natural extensions. Triangulate these behavioural measures against the per-condition self-report questionnaire collected in the same study; add eye-tracking to decompose latency; and replicate at a sample size informed by the power table above.
